# ExamAI

Локална платформа за тестове и обучение с директни профили за учители и ученици. Запазена е съществуващата архитектура: Java 21, Spring Boot 4, MySQL, React/TypeScript и Vite. Учебните операции използват API `/api/v1`, без избор или създаване на училище. Достъпът се проверява по роля, собственост и възлагане; старият API за тестове е изключен.

Приложението е реализирано за локална проверка, не е обявено за готово производствено внедряване. Провереното, външните интеграции и оставащите ограничения са в [отчета](docs/ACCEPTANCE.md).

Backend-ът следва `Controller -> Service -> Repository`, с централизирана обработка на exceptions и архитектурни тестове. SQL заявките за работното пространство са отделени в repositories. Подробности и примерен поток: [Backend Structure](docs/BACKEND_STRUCTURE.md).

## Старт с MAMP

MySQL: `localhost:8889`, база `test_ai`, локален потребител/парола `quicktest`. Flyway прилага миграциите при стартиране. Началното зареждане добавя веднъж само четирите демо профила, без учебни данни. Рестартът не изтрива създадено съдържание и не възстановява премахнати профили.

Терминал 1:
```bash
cd /Users/ivelin/Desktop/UKTC/Java/backend
./gradlew bootRun
```

Терминал 2:
```bash
cd /Users/ivelin/Desktop/UKTC/Java/frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Frontend: **http://localhost:5173**. Backend: **http://localhost:8080**.
Ако портът е зает, първо проверете съществуващото приложение. Не стартирайте две backend инстанции върху една и съща локална база без необходимост.

Нужни са Java 21 и Node.js 24 LTS или съвместима по-нова версия. Gradle wrapper и npm lock файлът са в хранилището. За друга база задайте `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD` в средата на backend процеса. `.env.example` съдържа само локални примерни настройки. Spring Boot не зарежда автоматично коренния `.env`; експортирайте нужните променливи преди старт. Vite чете `frontend/.env` или експортирания `VITE_API_URL`.

При нужда администраторът на локалния MySQL изпълнява:
```sql
CREATE DATABASE IF NOT EXISTS test_ai CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'quicktest'@'localhost' IDENTIFIED BY 'quicktest';
GRANT ALL PRIVILEGES ON test_ai.* TO 'quicktest'@'localhost';
```

MAMP 5.7 е проверен локално, но Hibernate предупреждава, че тази версия не е поддържана. За нова среда е предвиден MySQL 8.4.

## Основен Поток

Всяка група получава автоматично код за присъединяване, включително вече съществуващите групи след обновяване на backend. Учителят вижда и копира кода в „Групи“ и настройките на групата. „Нов код“ в настройките генерира различен код и отменя стария веднага; настоящите участници, възлагания и резултати се запазват. Ученикът отваря „Групи“, въвежда кода в „Присъедини се с код“ и се добавя сам. Ръчното добавяне от учителя остава достъпно. При добавяне от учителя, присъединяване с код или приемане на покана новите членове автоматично получават и вече възложените на групата тестове със същите срокове, кодове и разрешен брой опити. Повторното добавяне не дава допълнителни опити и не възстановява изрично отнет достъп до тест.

1. Потребителят се регистрира като учител или ученик / студент и потвърждава имейла си.
2. Учителят създава незадължителни групи и чернова ръчно, от банка с въпроси или чрез AI. Публикува неизменяема версия.
3. Възлага версия на групи/индивидуални получатели, задава срок и опити. Кодът се вижда в учителската таблица с възлаганията и след презареждане. От съответния ред може да се генерира нов код, да се копира или да се изпрати по имейл. За старите възлагания без запазен код се генерира нов.
4. Обучаемият влиза със своя профил, въвежда код и разрешава цял екран. Всеки въпрос има сървърен срок. Следващият се отваря едва след готовност.
5. Учителят проверява свободните отговори, запазва точките и отделно публикува резултат. Корекциите създават нови ревизии и известия.
6. Учениците решават възложените им тестове без лични плащания и без зависимост от училищен абонамент.

В „Възлагания“ търсенето над таблицата филтрира по име на тест и по име на възложена група. Двата филтъра се комбинират, работят с част от името и не различават малки и главни букви. „Изчисти филтъра“ връща всички възлагания, без да променя формата за създаване.

При строг режим излизане от цял екран или скриване на активния въпрос носи 0 точки; само blur не санкционира. Браузърът не може да гарантира липса на преписване или да блокира външни приложения. Мобилният строг режим е изключен по подразбиране; използвайте индивидуално одитирано изключение или го включете само след реална проверка на поддържаните устройства.

Условието на всеки въпрос има редактор с удебелен текст, курсив, подчертаване, зачеркване, горен/долен индекс, списъци и подравняване. „Формула“ отваря визуален редактор за степени, корени, дроби, суми, интеграли и гръцки букви; щракване върху добавена формула я отваря за промяна. Има и незадължително въвеждане чрез LaTeX. Форматирането се запазва и се показва в библиотеката, изпита, учителската проверка и ученическите резултати.

Всеки тест получава уникален 12-цифрен номер, видим в „Тестове“, включително съществуващите тестове след обновяване на backend. Номерът се запазва при редакция. Учителят го копира от таблицата и го споделя с друг учител, който го въвежда в „Номер на тест“ и избира „Добави по номер“. Това дава достъп до копие на последната запазена и публикувана версия, включително въпросите, отговорите и изображенията. Получателят получава собствен тест с нов номер, готов за редакция и възлагане. Повторното въвеждане връща вече добавеното копие; изтрито копие може да се добави отново. Промени и изтриване на оригинала не променят съществуващото копие. Чернови без публикувана версия и изтрити оригинали не могат да се добавят по номер. Възлагания, ученици, опити и резултати не се копират.

## AI

Учителят може да качи лекция или презентация при създаване на тест с AI и при добавяне на нови AI въпроси. Поддържат се PDF с избираем текст, PPTX, DOCX и UTF-8 TXT до 8 MB и 100 000 символа извлечен текст (PDF до 200 страници). След успешно качване се включва „Генерирай тест по качения материал“; изключването ѝ връща генерирането по тема. При включена отметка AI получава материала като източник и задача да използва само съдържащите се в него факти. Прегледайте генерираната чернова преди публикуване. Оригиналният файл не се запазва; извлеченият текст остава в защитената AI заявка за повторна обработка.

В редактора на ръчно създаден или AI тест всеки въпрос има „Подмени с AI“. Генерира се един заместващ въпрос с предварително попълнени тип и трудност. Учителят преглежда предложението и избира „Подмени въпроса“; точките, времето, останалите въпроси и настройките на теста се запазват. Промяната влиза в теста при обичайното запазване, а вече възложените версии остават непроменени.

`AI_PROVIDER=openai` (по подразбиране) използва OpenAI Responses API с валидиран структуриран JSON. Ключът е само на backend сървъра, никога във frontend или Git. Абонаментът за ChatGPT не включва API кредит.

За локален старт конфигурирайте ключа еднократно от корена на проекта. Скриптът го въвежда скрито и записва `.local/openai.properties` с права `600`, извън Git. Backend зарежда този файл и след рестарт; зададен в средата `OPENAI_API_KEY` има предимство.
```bash
bash scripts/configure-openai.sh
cd backend
./gradlew bootRun
```

`OPENAI_BASE_URL=https://api.openai.com/v1`, `OPENAI_MODEL=gpt-4.1-mini`, `OPENAI_TIMEOUT_SECONDS=180`. Локалният Ollama адаптер е премахнат. Заявките са със `store=false`; тема и учебен текст се изпращат към OpenAI, затова не включвайте лични данни. API използването има отделно таксуване и лимити. Ключ, публикуван в чат или Git, трябва да се оттегли и смени.

Бутонът „С AI“ в библиотеката отваря отделна страница за създаване на тест. AI заданията са асинхронни, резервират квота атомарно, валидират структурирания резултат и не публикуват тест. Резултатът се отваря автоматично в редактора. Учителят го преглежда и избира „Запази теста“: тестът се запазва, създава се валидирана версия за възлагане и се отваря библиотеката с тестове. При невалидни въпроси редакторът остава отворен. Невалиден резултат/timeout освобождава резервацията; повторение е изрично и ограничено. При липсващ ключ, кредит или достъп се показва конкретна грешка.

`AI_PROVIDER=mock` е **фиктивен локален адаптер** за тестове, не реално AI. Използва се по подразбиране само в Compose. Ръчното създаване не зависи от AI. Не поставяйте лични ученически данни в учебния изходен текст.

При създаване с AI опцията „С AI изображения“ и полето „Въпроси с изображение“ добавят автоматични илюстрации към първите избрани въпроси. Моделът подготвя съответстващи въпроси и описания за анатомични схеми, геометрични фигури, карти и други учебни изображения. Снимките се запазват като защитени PNG/JPEG файлове и могат да се увеличават, сменят или премахват в черновата. Преглеждайте точността на схемите преди запазване; AI може да греши. Реалното генериране на изображения се таксува допълнително от OpenAI и изисква достъп до `OPENAI_IMAGE_MODEL` (по подразбиране `gpt-image-2.5-flare`). Използва се [официалният Image API](https://developers.openai.com/api/docs/guides/image-generation). При неуспех заявката се маркира като неуспешна, без частично записани изображения. Локалният mock връща само тестова геометрична схема.

В таблицата „Проверка на опити“ всеки чакащ опит има „AI проверка“ и отделна ръчна проверка. AI оценява непроверените предадени текстови отговори според критериите и **публикува резултата автоматично**, включително известието до ученика. Точките се валидират спрямо максимума за всеки въпрос; автоматично оценените, вече ръчно проверените и приключилите без отговор въпроси се запазват. Текстовите въпроси с изображения се проверяват ръчно. Към OpenAI се изпращат въпросите, критериите и предаденият текст, без профилни данни, чернови и сесийни ключове; текстът на самия отговор може да съдържа лични данни и изисква подходящо основание за обработка. AI може да греши: публикуваната оценка остава достъпна за ръчна корекция. Неуспешна проверка не променя точките и не публикува резултат; изрично повторение е възможно до три обработки. Промени от ръчна проверка или отнет достъп по време на AI обработката отменят автоматичното публикуване.

В „Проверка“ филтърът „Предадени от / до“ избира включително началния и крайния ден по местното време на браузъра. Таблицата показва текущия код за достъп и позволява още един опит на конкретен ученик от възложената група след изчерпване на опитите, при неизтекъл срок и без активен опит. Предишните отговори и резултати се запазват. „Изпрати резултата“ използва актуалната публикувана оценка и изпраща линк към защитения ученически преглед.

Отметката „Преглед от ученика“ разрешава преглед на конкретен приключен опит. По подразбиране е изключена. След публикуване на резултата ученикът вижда бутон за преглед в „Опити и резултати“ само за разрешените опити и може да отвори въпросите, изображенията и собствените си отговори. Верните отговори, критериите и обясненията следват настройката „Верни отговори след срока“. Изключването на отметката спира достъпа и през директен линк, без да скрива оценката.

В „Проверка на опити“ търсенето по име на ученик и по група се комбинира с периода по дата. До ученика се показват групите на възлагането. Колоната „Резултат“ показва напълно верните отговори спрямо всички въпроси и процента от публикуваните точки. Частичните точки участват в процента. Непубликувана корекция не променя показания резултат; чакащите проверка опити още нямат окончателни стойности.

## Имейл, Google И Stripe

За Railway е добавен HTTPS адаптер за Resend. Настройките и стъпките за активиране са в [Имейл с резултат от Railway](docs/RAILWAY_EMAIL.md). Нужни са акаунт в Resend, потвърден собствен домейн и API ключ в backend Variables; няма нужда от SMTP портове.

На началния екран има „Влез с Google“ и „Регистрация с Google“. Името и потвърденият имейл се вземат от Google и не е нужна локална парола. Новият профил избира роля на отделен екран преди основната страница; повторният вход запазва съществуващата роля. Ако имейлът вече е регистриран с парола, първо влезте с нея и свържете Google от „Профил“.

За активиране създайте OAuth client от тип **Web application** в [Google Cloud](https://developers.google.com/identity/openid-connect/openid-connect), настройте consent screen и тестови потребители. Добавете Authorized redirect URI `http://localhost:8080/login/oauth2/code/google` и изпълнете:
```bash
bash scripts/configure-google.sh
```
Скриптът приема **Client ID** и **Client Secret**, записва ги в `.local/google.properties` с права `600`, извън Git. Това не е Gmail App Password. Рестартирайте backend; без OAuth ключове бутоните остават неактивни. При друг backend адрес регистрирайте точния му callback в Google Cloud, задайте `BACKEND_URL` и `FRONTEND_URL` за съответните приложения. Реален Google вход изисква тези настройки и отделна проверка с вашия профил.

`MAIL_ADAPTER=local` не изпраща външен имейл. Известията се виждат само от съответния профил в локалната тестова пощенска кутия. `smtp` използва конфигуриран SMTP, с allowlist за домейните на получателите. `sent` означава приемане от адаптера/SMTP, не доказано доставяне. Неизвестен резултат от изпращане се маркира `uncertain` и не се повтаря автоматично.

За изпращане през Gmail или Google Workspace включете двустепенна проверка и създайте [App Password](https://myaccount.google.com/apppasswords). От корена на проекта изпълнете:
```bash
bash scripts/configure-gmail.sh
```
Скриптът пита за адреса на изпращача, въвежда App Password скрито и приема домейните на получателите, разделени със запетая. Запазва настройките в `.local/mail.properties` с права `600`, извън Git. След рестарт backend проверява SMTP входа и изпраща през `smtp.gmail.com:587` със задължителен STARTTLS. Бутонът с плик добавя кода в опашката за имейл до възложените ученици с потвърден адрес. За адреси извън избраните домейни пуснете скрипта отново и добавете домейна. Демо адресите `@quicktest.local` не са реални пощенски кутии. Адресът за вход в писмото е `FRONTEND_URL`; за получатели на други устройства използвайте достъпен за тях адрес.

Google OIDC и SMTP са конфигурируеми адаптери. Старите организационни Stripe HTTP маршрути са премахнати; вътрешният адаптер е запазен за исторически данни и тестове. Без ключове са явно неактивни. Настройките, callback адресите, подписаните webhook събития, платежният портал и безопасното изпитване са описани в [INTEGRATIONS.md](docs/INTEGRATIONS.md). Няма live плащания. Страницата след Checkout не активира абонамент.

## Compose

```bash
docker compose up --build -d
docker compose logs -f backend
```

Портовете са отделени от MAMP: frontend **http://localhost:5174**, backend **http://localhost:8082**, MySQL **8890**, Mailpit **http://localhost:8025**. По подразбиране AI е фиктивен, а mail адаптерът е локален. `COMPOSE_MAIL_ADAPTER=smtp` насочва тестовите писма към Mailpit; `COMPOSE_AI_PROVIDER=openai` и `OPENAI_API_KEY` включват реалния OpenAI API. Спрете чрез `docker compose stop`. Не изтривайте database volume, за да поправяте миграции.

Compose е подготвен и YAML е проверен, но Docker не е наличен на тази машина: целият контейнерен старт трябва да се провери на среда с Docker.

## Тестове

```bash
cd backend
./gradlew test
```

Изолиран MySQL тест, никога върху `test_ai`:
```bash
EXAMAI_TEST_DATABASE_URL='jdbc:mysql://localhost:8889/examai_verification?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC' \
EXAMAI_TEST_DATABASE_USERNAME=root EXAMAI_TEST_DATABASE_PASSWORD=root \
./gradlew test --tests com.quicktest.WorkspaceTests --rerun-tasks
```

Създайте предварително отделната празна схема с локалния DB администратор. Тестът отказва URL към `test_ai`. Тестовите потребители са само в домейна `example.test`.

```bash
cd frontend
npm run build
npm run lint
npm run test:e2e
E2E_HEADED=true npm run test:e2e
```

Browser тестът създава отделно маркирани E2E профили и организации в конфигурирания локален backend, без да променя съществуващите тестове. Използва Chrome на Mac или `CHROME_PATH`. За друга среда задайте `E2E_API_URL` и `E2E_FRONTEND_URL`. Артефактите са в `.artifacts/`, извън git. Headed автоматизацията не заменя цялата ръчна cross-browser проверка.

Натоварване: същата MySQL тестова настройка с `EXAMAI_LOAD_TEST=true` и `--tests com.quicktest.WorkspaceLoadTests`. Измерването използва реални HTTP state/answer операции с 200 едновременни ученици; външните AI/SMTP заявки са изключени. Средата и измерените p95 са в отчета.

За production са нужни отделна база и тайни, HTTPS, `DEMO_SEED=false`, `LEGACY_API_ENABLED=false`, реална поща, одобрени политики и външни проверки. Профилът `production` отказва опасни демо настройки. Не публикувайте локалните демо акаунти.
